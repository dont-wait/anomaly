# Manual anomaly test dataset

This directory contains the **fixture generator only**. It creates a local
JSON file; it does not call the API or write to EventStoreDB/MongoDB.

## Generate

From the repository root:

```bash
python3 -m venv tools/test-data/.venv
tools/test-data/.venv/bin/python -m pip install -r tools/test-data/requirements.txt
tools/test-data/.venv/bin/python tools/test-data/generate.py
```

The default command creates:

- 6 source accounts: A-F;
- 8 receiver accounts used by the baseline/probe instructions;
- 30 completed baseline transfer records for each source account;
- no probe transactions, because those are performed manually;
- a reproducible fixture using seed `20261110` and reference time
  `2026-11-10T12:00:00Z`.

The output is written to `tools/test-data/output/anomaly-a-f.json`, which is
ignored by Git because it contains local test credentials.

Use another seed, reference time, or output path when needed:

```bash
tools/test-data/.venv/bin/python tools/test-data/generate.py \
  --seed 42 \
  --reference-time 2026-11-10T12:00:00Z \
  --output /tmp/anomaly-a-f.json
```

## Cases

| Account | Case | Manual probe described in the JSON |
| --- | --- | --- |
| A | `normal` | 20,000 VND to the familiar receiver, on the familiar mobile device/channel |
| B | `amount_spike` | 100,000 VND to the familiar receiver (5x the typical 20,000 VND) |
| C | `new_receiver` | 20,000 VND to a receiver not present in C's baseline |
| D | `new_device` | 20,000 VND from a new device, with familiar receiver/channel |
| E | `velocity_burst` | 6 manual requests, 15 seconds apart; expected positive label starts at request 3 |
| F | `contextual_amount` | 100,000 VND through the less-used web channel to a new receiver, using the familiar device |

The JSON is a dataset contract for the development/test importer. It is not
safe to import by directly inserting MongoDB documents: the importer creates
canonical history through EventStoreDB.

## Import into the local banking stream

After generating the fixture, run the development-only importer from `server/`:

```bash
cd server
APP_ENV=development \
SEED_DEMO_ENABLED=true \
make seed-anomaly-data
```

The importer creates the accounts, marks them KYC verified, funds their
post-baseline balances, and appends `TransferCreated`/
`TransferCompleted` historical events to EventStoreDB. It does not write
MongoDB directly. Start the banking projector and relay afterwards so MongoDB
projections and model feature state catch up:

```bash
make start-worker
make start-relay
```

The importer writes `anomaly-a-f.imported.json` beside the fixture. It contains
the actual account numbers generated by the backend and is ignored with the
fixture output directory. Re-running the importer is idempotent for the same
fixture; it does not reset balances after a manual probe has been performed.
